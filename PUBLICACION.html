    Publicación en una dirección

    Forgejo conserva el principal privado. Su espejo privado de GitHub recibe ramas y etiquetas. Los publicadores de GitHub generan las distribuciones públicas; ninguno escribe en Forgejo. Las etiquetas y los archivos publicados no se reemplazan por otros de contenido diferente.

    Headscale Gateway: compilación pública

    Desde la entrega 1.4.9, el control de headscale_gateway_releases compila en runners públicos estándar. Así no depende de la cuota de ejecución del espejo privado. Los publicadores antiguos del espejo se retiraron del árbol actual para evitar entregas duplicadas; la comprobación de calidad de pull requests se conserva. Lee la API de Forgejo con un token limitado y descarga solo el árbol de fuentes de la etiqueta publicada; no copia el historial privado.

    Sus fuentes se mantienen primero en packaging/releases/automation/ y packaging/releases/.github/workflows/ del principal de Forgejo. Exportar ese control al repositorio público es una tarea de mantenimiento por SSH; no se necesita repetirla para cada versión normal de la aplicación.

    1. Prepara las fuentes y VERSION con tools/set_version.py, los cambios de uso y los instaladores generados del manifiesto. Revisa y sube por SSH a Forgejo.
    2. Publica allí una release estable vX.Y.Z, con VERSION coincidente y el commit preparado. Una etiqueta sola, un borrador o una prerelease no publica.
    3. El flujo Compilar y publicar desde Forgejo consulta las releases cada hora, en el minuto 17 UTC. También se activa al actualizar su controlador en main. No hace falta lanzar flujos a mano. GitHub puede retrasar sus programaciones.
    4. Cada trabajo descarga el mismo commit y vuelve a comprobar etiqueta, versión y manifiesto. Seguridad Go/npm, pruebas Go/JS/Python, Windows, Debian, integración Home Assistant y contenedores preceden a la entrega. Un fallo bloquea la publicación de instaladores.
    5. El runner construye Android con la identidad de firma existente y Lint, los seis motores, bandejas, Debian/Fedora, fuentes correspondientes y Flatpak. Instala y comprueba Flatpak y compila el manual estricto antes de publicar.
    6. Se actualizan paquetes, tiendas y ambas ramas gh-pages. Las tiendas conservan las otras aplicaciones. Se publican las descargas en cuatro repositorios y se comprueban todas sin credenciales y por SHA-256. Un recibo con el commit Forgejo y el controlador identifica la entrega completada y evita repetirla.

    La etiqueta 1.4.9 conserva su commit original aunque después cambien el control o las guías del principal. No se mueve una etiqueta para corregir automatización. Una publicación parcial requiere revisar los resultados originales y completar su recuperación; no recompilar para sustituir archivos ya distribuidos.

    Secretos del control público

    Los siguientes secretos se guardan en Actions de headscale_gateway_releases:

    • FORGEJO_RELEASE_READ_TOKEN: solo wolfbelmi88/headscale_gateway, permiso repository en Leídas y el resto sin acceso. No permite escribir en Forgejo.
    • PUBLICATION_TOKEN: token GitHub fine-grained con Contents de lectura y escritura solo en los seis destinos públicos de Headscale de la tabla. No necesita Administration, Workflows ni acceso al espejo privado.
    • ANDROID_SIGNING_BUNDLE: la firma Android existente. Nunca crear otra clave para una actualización: impediría actualizar las instalaciones actuales.

    GitHub no permite recuperar los valores guardados. Para cambiar de repositorio compilador hay que volver a introducirlos en sus secretos cifrados. No se pegan en incidencias, conversaciones ni archivos Git. La prueba de lectura comprueba API, archivo de fuentes, SSO y firma sin compilar; la prueba de publicación usa git push --dry-run sin modificar referencias.

    Los tokens tienen caducidad: renuévalos antes de su fecha límite. GitHub desactiva las programaciones de repositorios públicos después de 60 días sin actividad; si sucede, el mantenedor debe reactivar el flujo. El principal sigue siendo privado y todas las compilaciones grandes se ejecutan fuera del Linux del usuario.

    Descargas públicas y nuevos paquetes Linux

    Las instantáneas saneadas completas se publican en upstream-source del paquete YunoHost y en etiquetas source-vX.Y.Z, sin claves, bases de datos ni historial privado. Su main contiene solo el paquete YunoHost. Los binarios del motor y sus fuentes correspondientes se sirven desde server-vX.Y.Z en ese mismo destino.

    Los instaladores de bandeja son archivos pequeños completos. Los fuentes exactos de Electron/Chromium/FFmpeg, Node y NAN se distribuyen en una release propia desktop-sources-electron-VERSION-HUELLA, reutilizada mientras no cambie el lock. Se mantienen fuentes exactos, parches, avisos y sumas, con enlace desde cada instalador y release Gateway. El publicador comprueba el conjunto antes de publicar los instaladores; rechaza fuentes distintos y no reemplaza adjuntos. La release de dependencias no ocupa «Latest». La 1.4.16 conserva todos sus archivos y enlaces originales; la separación se aplica a las siguientes entregas. Solo el archivo grande de fuentes Chromium usa partes. Conserva esos fuentes y avisos al redistribuir el escritorio. No elimines una release de dependencias mientras existan instaladores que la referencien. Cada release tiene su propio SHA256SUMS: no intercambies el de Gateway con el de los fuentes de Electron.

    Antes de preparar otro conjunto, el workflow consulta de forma anónima el existente. Si coincide con el lock, omite por completo la preparación y subida. Solo un 404 de la release permite preparar uno nuevo; una suma distinta, un adjunto ausente o un error de acceso bloquean el proceso. El constructor y el publicador también rechazan los archivos de terceros en la carpeta de adjuntos de Gateway. El ensayo automatizado de una versión siguiente no crea etiquetas, no cambia VERSION y no publica una nueva aplicación.

    El mismo manual se genera desde las fuentes y se publica en gh-pages de YunoHost y Home Assistant. Android utiliza la dirección estable https://gente-del-condado.github.io/headscale_gateway_ynh/. Renombrar un repositorio conserva releases y permisos, pero sus enlaces Pages deben actualizarse expresamente.

    Consulta Debian y Fedora, Flatpak y descargas públicas. Flatpak distribuye el motor completo, consola y panel web. No se solicita inclusión en Flathub ni en el catálogo YunoHost. Play Store continúa solo preparado: el AAB no se envía a la tienda.

    Los resultados históricos del laboratorio real YunoHost se conservan en sus commits y notas; los informes privados se archivan fuera del árbol de desarrollo. Las pruebas nginx/NSS en contenedor son complementarias; no equivalen a repetir package_check o la actualización de una instalación real con datos y secretos. No ejecutes máquinas virtuales ni compilaciones grandes en el Linux del usuario.

    PiVigia y JackSignal

    Sus flujos reciben el espejo desde Forgejo y publican directamente en GitHub tras calidad correcta del mismo SHA de main. Los pull requests no publican. Sus secretos PUBLICATION_TOKEN permanecen en los respectivos principales privados, limitados a sus destinos públicos. Esta migración del compilador de Headscale no cambia sus credenciales ni sus flujos.

    Imágenes precompiladas de Home Assistant

    Forgejo sigue siendo el origen y GitHub el espejo. El publicador entrega el contenido aprobado a build-source de Mis_app_ha. Un único workflow de esa tienda construye imágenes nativas amd64 y aarch64, ejecuta las pruebas de arranque con datos desechables y crea un índice multi arquitectura en GHCR. Solo después de verificar su descarga anónima actualiza la aplicación en main y añade image:. La versión anterior sigue instalable mientras se prepara la nueva.

    Los Dockerfile y fuentes se conservan; Home Assistant descarga la imagen preparada. No se cambian slugs, opciones, volúmenes, permisos, datos ni credenciales. Una imagen ya distribuida no se sustituye con otro contenido: aumenta la versión al cambiar el contexto de compilación. El cambio inicial publica las versiones actuales sin forzar actualizaciones ni reinstalaciones de los equipos existentes.

    El controlador común se mantiene en packaging/homeassistant-store/ de headscale_gateway en Forgejo y se exporta a .github/ha-images/ y al workflow de Mis_app_ha. No escribe en los principales ni devuelve cambios a Forgejo.
